# 上线前验证清单

本项目当前没有可直接在此工作目录运行的 PHP 环境。部署到测试服务器后，先运行下面的语法检查，再执行本清单；任何失败项都不应直接上线。

```bash
find . -name '*.php' -not -path './releases/*' -print0 | xargs -0 -n1 php -l
```

## 1. 后台安全

- 连续使用错误密码登录 5 次：第 6 次应被限制，并显示通用提示，不泄露账号是否存在。
- 刷新登录页后，浏览器的 `PHPSESSID` 应保持不变；`data/sessions/` 中应能看到 PHP 创建的会话文件。
- 正确登录后，检查响应 Cookie：应包含 `HttpOnly`、`SameSite=Lax`；HTTPS 下还必须有 `Secure`。
- 在新标签中提交一个没有 `csrf_token` 的后台 POST：应失败，不产生写入。
- 修改管理员密码后，用修改前已登录的浏览器刷新后台：应退出登录。
- 退出登录后，后台页面应跳转到登录页。

## 2. 文件与更新

- 上传大于 50 MB、非 ZIP、含 `../` 或符号链接的升级包：应被拒绝。
- 上传含 `includes/db.php`、`data/`、`uploads/`、`.env` 的普通源码包：应成功暂存；下载暂存后的发布包确认上述内容已被自动剔除。
- 正常升级包必须带 64 位 SHA256；将 update.json 的哈希改错后，更新应中止且不写入文件。
- 执行一次测试更新失败场景：确认自动备份存在，且站点能恢复。
- 访问 `/data/`、`/includes/`、`/install/`：服务器应返回 403 或 404（Nginx 需按 `docs/deployment-security.md` 配置）。

## 3. 公开接口与前台

- `GET /api/visit.php` 应返回 405；一分钟内重复 POST 应返回 429。
- 留言板跨域 POST 或没有来源页的请求应返回 403；同一用户一分钟内第二次提交应返回 429。
- 用键盘操作首页主题菜单：Tab 聚焦、Enter 选择、方向键移动、Escape 关闭均应可用。
- 在 360px、768px、1440px 宽度和浅色/深色/减少动态效果设置下检查页面；没有横向滚动、文字遮挡或不可见焦点。

## 4. 建议的自动化补充

- 在 CI 中执行 PHP 语法检查和依赖漏洞扫描。
- 用 Playwright 或 Cypress 覆盖登录、修改密码、留言、作品墙图片加载和主题菜单键盘操作。
- 用 Lighthouse 在移动网络条件下记录 LCP、INP、CLS；把关键指标和测试日期保存到发布记录。
