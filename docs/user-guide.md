# 用户手册

> 适用版本：V1.24 及以后版本  
> 适合人群：已经完成部署、需要日常维护站点的站点管理员。  
> 若尚未安装，请先阅读 [安装说明](installation.md)。

---

## 1. 后台入口和登录

后台地址通常是：`https://你的域名/admin/login.php`。

输入安装时创建的管理员账号和密码后登录。账号与密码均区分大小写，例如 `Admin` 和 `admin` 是不同写法。登录完成后，不使用时请点击“退出登录”。

## 2. 日常功能在哪里

后台左侧菜单中常用的功能包括：

- **仪表盘**：查看网站概况；
- **站点配置**：修改网站标题、介绍、联系方式等；
- **链接管理**：维护友情链接或社交链接；
- **作品墙**：添加、编辑、排序展示作品；
- **留言板**：审核或回复访客留言；
- **备份恢复**：创建代码备份、出现问题时恢复；
- **云更新**：检查、确认和安装新的源码版本；
- **修改密码**：更换后台管理员密码。

修改内容后，请使用页面上的保存按钮。建议每次大改前先到“备份恢复”创建一次备份。

## 3. 修改管理员密码

1. 登录后台后，点击“修改密码”。
2. 输入旧密码、新密码和再次确认的新密码。
3. 保存成功后，系统会让所有旧登录状态失效，需要使用新密码重新登录。

请不要使用容易猜到的密码，也不要把密码保存到公开文档或截图中。

## 4. 云更新是什么

云更新用来把新版源码安全地发送到已部署的网站。它分成两个位置：

- **云更新管理**：上传和保存新版压缩包的地方，地址通常是 `https://更新源域名/update-admin/`；
- **云更新**：已部署网站后台中的更新页面，地址通常是 `https://网站域名/admin/update.php`。

可以把前者理解为“版本仓库”，后者理解为“需要接收更新的网站”。同一台服务器上也可以同时存在两者。

## 5. 第一次配置云更新

### 第 1 步：在云更新管理中上传版本包

1. 登录 `update-admin` 页面。
2. 在“新版本号”填写版本，例如 `1.24`。
3. 版本号必须是 **x.xx** 格式：主版本号 1 位、次版本号 2 位。
   - 正确：`1.00`、`1.24`、`2.35`；
   - 错误：`1.2`、`1.241`、`10.24`。
4. 选择源码 ZIP 文件。
5. 系统会尝试读取 ZIP 内的 `更新记录.txt`，自动填入“更新说明”；你可以补充或修改。
6. 点击“上传并暂存为待更新包”。

上传后，系统会自动从升级包中剔除以下本地数据和敏感内容：

- `includes/db.php`；
- `data/`；
- `uploads/`；
- `install/`；
- 环境配置文件、安装锁等。

所以可以直接上传普通源码 ZIP；数据库密码、用户上传文件和网站数据不会被放进云更新包。

### 第 2 步：记下更新源地址

上传成功后，右侧会显示类似下面的地址：

```text
https://更新源域名/update-admin/update.json
```

这就是“更新源地址”。不要把它写成 ZIP 地址，也不要漏掉 `update.json`。

### 第 3 步：在要更新的网站保存更新源

1. 登录需要更新的网站后台。
2. 打开左侧“云更新”。
3. 在右侧“update.json 地址”粘贴第 2 步的地址。
4. 点击“保存”。
5. 点击“检查更新”。

首次没有上传任何版本包时，页面会提示先上传并暂存版本包；这是正常提示，不是网站故障。

## 6. 正常更新流程

每次发布新版，按下面顺序操作：

1. 在本地确认新源码可以正常打开；
2. 确认 `更新记录.txt` 已写明这次修改内容；
3. 打开云更新管理，上传 ZIP、填写规范版本号和更新说明；
4. 确认版本库中显示“待确认”；
5. 登录目标网站后台，进入“云更新”；
6. 点击“检查更新”；
7. 在弹出的确认窗口核对版本号、日期、更新说明和压缩包信息；
8. 点击“确认更新”；
9. 等待页面显示成功，不要在更新过程中关闭页面、重启 PHP 或删除文件；
10. 更新后刷新网站首页和后台，确认主要页面正常。

点击“取消”只会暂时关闭本次自动提醒；之后主动点击“检查更新”时，确认窗口会再次出现。

## 7. 一键更新和确认更新的区别

- **确认更新**：用于“待更新包”。这是日常推荐的方式，因为你能先看到版本和更新说明，再决定是否安装。
- **一键更新**：用于更新源已经发布了高于本地版本的正式版本。它会直接开始更新，因此点击前也应先阅读页面上的版本信息。

无论使用哪种方式，系统都会先下载压缩包、核对 SHA256 校验值、创建自动备份，再解压更新文件。校验不通过时不会继续安装。

## 8. 云更新不会覆盖什么

为了保护线上数据，云更新不会覆盖：

- 数据库配置 `includes/db.php`；
- 网站版本记录 `version.json`；
- `data/` 数据目录；
- `uploads/` 上传文件目录；
- `install/` 安装目录；
- `.htaccess` 和安装锁。

这意味着更新代码通常不会清空文章、留言、图片和数据库配置。若新版需要修改数据库结构，请先阅读该版本的更新说明，不要自行把数据库文件塞进升级 ZIP。

## 9. 如何查看更新日志

在后台“云更新”页面下方可以看到最近更新日志。日志会记录：

- 上传并暂存了哪个版本；
- 是否确认更新成功或失败；
- 下载、校验、备份、解压等关键步骤；
- 本次更新的更新说明。

更新说明会整理为一行显示，内容特别长时会自动截短。完整说明仍可在云更新管理的版本库中查看。

## 10. 更新失败怎么办

先不要反复点击更新。请按顺序检查：

1. 阅读页面上显示的失败原因和更新日志；
2. 确认服务器 PHP 已启用 `zip` 和 `curl` 扩展；
3. 确认 `data/` 目录和网站根目录可以被 PHP 写入；
4. 确认更新源地址可以在浏览器中打开，并返回 `update.json`；
5. 确认更新 ZIP 没有被删除，且网络可以访问；
6. 若页面提示 SHA256 校验失败，重新上传原始 ZIP，不要手动修改已发布的 ZIP 文件。

系统在真正写入新文件前会先备份；更新过程出错时会尝试自动恢复。仍无法恢复时，请使用下一节的手动恢复方法。

## 11. 如何回退或恢复

“回退”有两种含义，请不要混淆：

### 11.1 恢复已经更新的网站

1. 登录发生问题的网站后台。
2. 打开“备份恢复”。
3. 找到更新前自动创建的备份，通常名称中含有 `preupdate`。
4. 选择恢复，等待完成后刷新首页和后台检查。

这是网站出问题时最直接的恢复方法。

### 11.2 在云更新管理中改回旧版本

云更新管理的“版本库”中可对历史版本点击“回退到此”。这个操作会把旧版本重新标记为当前发布版本，并重建 `update.json`；它不会立刻修改其他网站的文件。目标网站仍需在后台检查更新并确认，才会安装该版本。

## 12. 每次更新前后的检查清单

### 更新前

- [ ] 已创建最新备份；
- [ ] 新源码在测试环境或本地检查过；
- [ ] 版本号符合 `x.xx`；
- [ ] `更新记录.txt` 写明了修改内容；
- [ ] ZIP 内没有手工放入数据库配置、数据目录和上传目录；
- [ ] 更新源地址可访问；
- [ ] 服务器磁盘还有足够空间保存临时 ZIP 和备份。

### 更新后

- [ ] 首页可以正常打开；
- [ ] 可以正常登录后台；
- [ ] 站点配置、图片和留言数据仍存在；
- [ ] 更新日志显示成功；
- [ ] 主要页面在手机和电脑上均可访问；
- [ ] 如有异常，立即停止继续操作并从“备份恢复”恢复。

## 13. 最重要的安全习惯

1. 使用 HTTPS，不要长期使用裸 IP 或 HTTP 登录后台。
2. 管理员账号和密码区分大小写，请妥善保存。
3. 数据库密码、宝塔 API 密钥和后台密码绝不发送到公开群聊、截图或代码仓库。
4. 更新前备份，更新后测试；不要跳过这两步。
5. 只上传自己确认过来源的 ZIP 更新包。
6. 定期更新服务器系统、宝塔面板、PHP 和数据库，但先备份再更新。

按照本手册操作，即使没有服务器基础，也可以完成部署和日常更新管理。
